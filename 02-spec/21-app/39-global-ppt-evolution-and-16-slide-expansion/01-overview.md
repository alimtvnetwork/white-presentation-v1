## 4. 1920 × 1080 Virtual Canvas & Adaptive Uniform Scaling

All layouts, coordinates, padding tokens, and font sizes are defined within a strict virtual reference space of **$1920 \times 1080$ pixels** (16:9 widescreen aspect ratio).

```
(0,0) -------------------------------------------------------- (1920, 0)
  |                                                                 |
  |   Header Area: Y=60px to Y=180px (Title, Kicker, Subtitle)       |
  |                                                                 |
  |   Main Content Stage: Y=220px to Y=960px (Cards, DAG, Tables)   |
  |                                                                 |
  |   Footer / HUD Zone: Y=980px to Y=1040px (Pills, Telemetry)     |
  |                                                                 |
(0,1080) ---------------------------------------------------- (1920, 1080)
```

### 4.1 Uniform Scaling Engine
At runtime, the presentation container evaluates the target viewport using a high-performance `ResizeObserver`:
1. Calculates the uniform scaling factor:
   $$\text{scaleFactor} = \min\left(\frac{\text{viewportWidth}}{1920}, \frac{\text{viewportHeight}}{1080}\right)$$
2. Applies hardware-accelerated CSS transform scaling:
   ```css
   .slide-stage-canvas {
     width: 1920px;
     height: 1080px;
     transform: scale(var(--stage-scale));
     transform-origin: center center;
     contain: layout paint;
     isolation: isolate;
   }
   ```
3. Guarantees zero aspect-ratio distortion, zero horizontal or vertical scrollbars, and razor-sharp rendering on 1080p, 1440p, 4K UHD, and 8K displays.

### 4.2 Pure DOM Live Typography Mandate
- **Zero Rasterized Text:** Flattening text into PNG, JPEG, or WebP graphics is strictly prohibited. All text must be live, accessible, and selectable DOM text.
- **Zero 2D Canvas Bitmap Text:** Using HTML5 `<canvas>` 2D bitmap text (`fillText`) is prohibited. Text must scale vectorially via the browser's native text layout engine.

## 6. 6-Tier HSL Token Architecture & Variable Clean-Pass Teardown

### 6.1 The 6-Tier HSL Token Contract
All color properties are authored strictly as space-separated unadorned HSL triplets (`H S% L%`), permitting dynamic alpha compositing via `hsl(var(--token) / <alpha>)`:

```
+---------------------------------------------------------------------------------------------------+
| 6-TIER HSL TOKEN ARCHITECTURE                                                                     |
+---------------------------------------------------------------------------------------------------+
| Tier 1: Canvas Base (60%)      --> --pres-canvas-bg, --pres-canvas-bg-hsl                         |
| Tier 2: Structural Surface(30%)--> --pres-card-bg, --pres-card-bg-hsl, --pres-card-border-hsl     |
| Tier 3: Primary & Secondary Ink--> --pres-text-primary, --pres-text-secondary, *-hsl              |
| Tier 4: Focal Brand Accent(10%)--> --pres-accent, --pres-accent-hsl, --pres-accent-glow           |
| Tier 5: 10-Step Gradient Stops --> --pres-gradient-stop-0-hsl through --pres-gradient-stop-9-hsl |
| Tier 6: Micro-Shadow & Glow    --> --pres-shadow-elevation, --pres-glow-spread                    |
+---------------------------------------------------------------------------------------------------+
```

### 6.2 Variable Clean-Pass Teardown Protocol
To prevent token retention bleed across dynamic slide transitions, the presentation runtime executes an active cleanup cycle before mounting any new slide theme:

```typescript
const MANAGED_PRES_VARIABLE_PREFIXES = [
  '--pres-',
  '--gradient-',
  '--gold',
  '--cream',
  '--ember',
  '--ink',
  '--accent-',
];

export function cleanPreviousThemeVariables(rootEl: HTMLElement): void {
  const inlineStyle = rootEl.style;
  const propertiesToRemove: string[] = [];

  for (let i = 0; i < inlineStyle.length; i++) {
    const propName = inlineStyle[i];
    const isManaged = MANAGED_PRES_VARIABLE_PREFIXES.some((prefix) =>
      propName.startsWith(prefix)
    );
    if (isManaged) {
      propertiesToRemove.push(propName);
    }
  }

  propertiesToRemove.forEach((prop) => inlineStyle.removeProperty(prop));
}
```

### 7.1 Key Invariants
1. **Immunity to Canvas Theme:** Switching from an obsidian dark theme to a white editorial light theme causes zero changes in HUD legibility.
2. **Guaranteed Contrast Ratio ($C_R \ge 12:1$):** Pure white text on deep slate carbon guarantees effortless navigation readability across all projection hardware.
3. **Strict Zero Style Bleed:** No presentation slide CSS rules can override `--chrome-*` tokens.

## 8. Mathematical Dual-Mode Contrast & Zero Yellow-on-Light Rule

High-luminance yellow, gold, and lime tokens that look stunning on dark OLED displays lose all optical contrast on light surfaces ($L > 0.35$). Module 39 enforces an automated dual-mode contrast engine:

- **On Dark Themes:** Accent text renders with vibrant luminescent saturation (`hsl(var(--pres-accent))`).
- **On Light Themes:** High-luminance accents automatically invert to deep ink overrides:
  - Gold / Yellow (`hsl(45, 95%, 50%)`) inverts to **Deep Umber** (`hsl(28, 80%, 25%)`, $C_R = 9.8:1$).
  - Bright Lime (`hsl(120, 95%, 45%)`) inverts to **Forest Emerald** (`hsl(155, 80%, 22%)`, $C_R = 10.4:1$).
  - Violet / Cyan inverts to **Sovereign Royal Navy** (`hsl(224, 75%, 26%)`, $C_R = 9.2:1$).
- **WCAG Compliance:** All primary and secondary text nodes strictly meet **WCAG AAA** ($C_R \ge 7.0:1$) against their parent surface.
